LinuxFlow-E2B

A coding harness that helps a small model (Gemma 4 E2B) write C. It gives the model only the relevant slice of a code graph instead of whole files, and rejects generated code that breaks a few simple safety and style rules before it is compiled.

1. Problem: Small Models Write Unsafe C

Autonomous LLM coding agents routinely generate syntactically plausible but catastrophic code when targeting systems languages like C and the Linux kernel. Common failure modes include unbounded cyclomatic branching, stack-allocated excess local variables, missing allocation checks (`kmalloc`), dangerous string operations (`strcpy`), and deep control indentation.

Traditional sandboxes rely solely on trial-and-error compiler execution, wasting expensive context windows and allowing memory bugs to slip past unit tests.

2. Approach: Code Property Graph Retrieval

LinuxFlow-E2B parses the codebase into an explicit multi-layer semantic graph using tree-sitter-c and SQLite storage, enabling sub-token ego-slice retrieval instead of dumping entire source files into context.

3. Rule Checks (Cedar Policies)

Every generated patch is checked against five rules (written as Cedar policies) before it reaches GCC:

RULE L1
V_local ≤ 5
Caps stack variables per function to eliminate stack frame bloating and register spill.
RULE L2
C_cyclomatic ≤ 5
Enforces guard clauses and early-return patterns, replacing complex nested if/else ladders.
RULE L3
D_indent ≤ 3
Limits nesting depth so generated functions stay flat and easy to review.
RULE L4
SLOC ≤ 35
Guarantees all functions fit within a 512-token Gemma 4 E2B sliding window.
RULE L5
C Memory Safety
Immediate allocation checks on kmalloc/malloc; ban on gets/strcpy/sprintf; forward-only goto cleanup.

Rule check before compiling: If a patch violates any of L1–L5, it is rejected in about 1 ms with a message naming the broken rule, and that message goes back to the model before any time is spent compiling.

4. Evaluation

Evaluated on a small benchmark written for this project, so treat these as early results rather than a standard comparison:

  • 25 kernel-style C tasks (linked lists, a slab-style allocator, mutex use, device-tree parsing): all 25 compiled with GCC and passed the rule check on the first attempt.
  • Token Optimization: 62.3% context reduction via Token-Oriented Object Notation (TOON) CPG digests compared to baseline markdown ego-slices.
