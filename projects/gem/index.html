GEM is a personal AI assistant that goes beyond chat. It retrieves live information from multiple sources, reasons about which tool to use, executes that tool on your local machine, and returns a grounded answer. Built when most LLM wrappers were still stateless chatbots. The interesting part was building the tool-use dispatch loop before LangChain normalized the pattern.

The loop

The failure mode of a naive LLM assistant is hallucination — it confidently invents file paths, command flags, and API responses. RAG is the fix: before the LLM reasons, relevant context is retrieved from real sources and injected into the prompt. The LLM then decides whether to answer directly or call a tool. If it calls a tool, the result comes back into the loop as new context. The answer is always grounded in something that actually happened.

Technical Highlights

1. Custom tool-use routing before frameworks existed

The dispatch logic — deciding which tool to call and with what arguments — was built from scratch. LangChain's tool-use abstraction didn't exist in this form yet.

2. RAG as a safety layer

Without retrieval grounding, the LLM would hallucinate shell commands. The retrieval step is not just for information — it's what makes local execution safe.

3. Voice pipeline latency

The round-trip speech→STT→retrieval→LLM→TTS→speaker has to feel responsive. Each stage was optimized independently to keep total latency under 3s.

Limitations

  • No persistent memory across sessions
  • Tool execution is sequential, not parallel
  • No execution sandboxing — trust is assumed
  • Single user only
